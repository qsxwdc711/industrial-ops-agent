# 工业智能运维系统设计

已确认的需求：Python 后端、React 前端、火山引擎方舟 API、水泵与电机场景；数据感知、分片与聚合、Multi-Agent、RAG/MCP、可视化五项功能。用户已要求开始执行。

## 方案选择

采用模块化单体加独立基础设施：相比立即拆分多个微服务，更容易在同一台电脑运行、调试和解释；相比只有前端模拟数据，可以验证真实 API、持久化和后台任务。模块之间通过服务接口和异步队列交互，之后可以拆分。

## 架构与数据流

- React + TypeScript + Vite 提供概览、设备、告警、知识库、助手五个页面。
- FastAPI 提供 REST API 和诊断 SSE；SQLAlchemy 支持 SQLite 本地开发和 MySQL 部署。
- 接入先保存持久化收件箱，再经过解析、计算、存储三级队列；设备编号 SHA256 对固定分片数取模，禁止在已有数据时直接改分片数。
- 本地 asyncio.Queue 便于启动；RabbitMQ 模式提供持久化消息、消费确认和重试。两种模式都有事件编号幂等和失败状态。
- 周期任务执行小时聚合；查询支持进程内 TTL 缓存或 Redis。50ms 与亿级数据是待压测目标。
- LangGraph 编排规划、逐步执行、分析与工具反馈。方舟模式通过兼容 OpenAI 的模型客户端实现规划和工具调用；无密钥时使用明确标识的规则演示模式。
- MCP stdio 服务提供设备指标、告警、日志三个只读工具。知识检索工具独立封装。模型接收到的是工具数据，不执行模型生成的 SQL。
- 文档按段落切片并保留来源。本地模式为关键词检索；Milvus 模式调用单独配置的嵌入模型并执行向量检索，失败时报告错误，不冒充向量检索。
- 方舟 API Key 仅留在后端环境变量，接口和前端不返回密钥。

## 错误与状态

数据事件状态、设备状态、告警处置状态、诊断任务状态分别存储。外部服务连接错误可见；真实模型调用失败不静默变成演示结果。诊断历史按会话分组，并保留工具证据与最终报告。限制请求长度、检索条数、工具轮次和并发诊断数。

## 验收

验证入库与去重、分片稳定性、告警生成与确认、知识切片与来源、诊断 SSE 与会话、MCP 工具、前端页面与交互；运行 pytest、TypeScript/build 和浏览器冒烟。Docker Compose 提供 MySQL、RabbitMQ、Redis、Milvus；真实方舟和嵌入调用需配置个人凭据，不将未验证能力写成已达成性能。

# 2026-10-15 测试问题修复设计

用户已授权修复上一轮测试发现的问题。本轮按现有接口完成修复与回归，在当前工作区保留上一轮测试文件，不执行提交或发布。

## 修复规则

1. 同一 event_id 重试时，若本次没有显式提供 timestamp，则使用首次收件箱记录的时间做比较；其他字段必须全部相等，任何实际数据变化仍返回 409。若显式提供 timestamp，继续比较它的归一化值。首次接收时间、历史记录与设备最新时间不因重试改变，不需要数据库迁移。
2. 问题和日志在输入模型内去除首尾空白，少于两个有效字符返回 422；正常内容保存清理后的文本。对空格、制表符、换行和 Unicode 空白采用同一规则。
3. 720px 以下的操作按钮组限制最大宽度、允许换行和收缩，不隐藏按钮，也不通过裁切页面掩盖溢出。验证五个页面和报告在既有测试宽度下的布局。
4. Redis 宿主端口默认改为 16381，并允许 REDIS_PORT 配置；同步本地配置示例、测试默认值和说明。Redis 镜像允许 REDIS_IMAGE 覆盖，以便保留现有缓存镜像及数据卷。容器内部端口继续为 6379，不更改 Windows 保留端口或其他项目。
5. 方舟聊天与嵌入请求默认不继承系统代理，ARK_TRUST_ENV=true 时显式恢复继承。聊天 HTTP 客户端由 FastAPI lifespan 创建、复用并关闭；不改变系统代理和模型凭据。

## 取舍

幂等比较选择复用首次接收时间，避免要求所有网关改为显式时间戳，也避免新增数据库列或修改已有数据。仅在本次请求省略时间戳时采用该规则，显式时间变化仍受校验。

代理只作用于项目的方舟客户端，不通过设置全局 NO_PROXY 或清空 Windows 代理修复。端口变更作用于本项目，原 Redis 卷在重建容器时保留。

## 验证与数据隔离

先运行三个失败测试，再补充显式时间戳冲突、其他字段冲突、并发重试和文本清理测试。随后运行全后端测试（含真实 MySQL/RabbitMQ/Redis/Milvus）、前端构建、真实模型浏览器 smoke 及全部浏览器验收。真实浏览器使用新的 SQLite 测试库、专用队列和向量集合，结束后清理并恢复服务状态。

初始失败证据保存在原测试报告和原始测试结果；新结果写入独立的修复后报告，保留前后对照。
